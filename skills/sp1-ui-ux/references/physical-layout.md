# Physical Layout & Playability Without Looking

The interface should be playable without looking at it. Position, grouping,
tactile expectation, and consistent semantics all contribute to this — not
just labeling.

- **Position** — see `control-grammar.md` for the persistent per-column
  semantic roles this depends on.
- **Grouping** — controls that form a relationship (functional or opposing,
  see `relationships.md`) should be laid out so their relationship is
  physically legible, not scattered.
- **Tactile expectation** — a player should be able to predict, from where
  a control sits, roughly what *kind* of thing it does before reading a
  label.

## Muscle memory as a goal, not a side effect

The player should eventually develop muscle memory for the *kind* of thing
each control does — not just where each individual instrument's controls
happen to be. This is the payoff of keeping the physical grammar stable
across pages and across instruments: a player moving from one SP-1
instrument to another should feel the grammar carry over even though the
musical meaning changes.

## Using this file

When laying out a new instrument's controls, check each control's position
against two questions: does this position match the persistent semantic
role of that column (per `control-grammar.md`), and does the layout make
any functional/opposing relationships it's part of visually or spatially
obvious?
