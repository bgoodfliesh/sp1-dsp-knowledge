# Feedback (Visual / LED Language)

**Status: not yet established.**

The source discussion that produced this skill's other principles didn't
cover how the instrument communicates state back to the player (LEDs,
displays, or other visual/tactile feedback) as its own topic. Rather than
invent a feedback grammar to fill this file out, it's left as an open
question.

When this does get worked out, it likely belongs here as its own layer,
parallel to the control grammar: e.g. does feedback follow the same
persistent-role-per-position idea as the controls themselves (a given LED
position always means the same *kind* of thing), and does it distinguish
Tier 1/2/3 the same way controls do.

## Using this file

Don't assume an answer here. If a design question depends on feedback
behavior that isn't decided yet, surface that explicitly rather than
guessing — and if a real answer emerges from that discussion, replace this
stub with it.
